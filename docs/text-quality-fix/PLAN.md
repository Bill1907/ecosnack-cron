## 2. 핵심 결정

| 결정 | 선택 | 이유 |
|---|---|---|
| 막는 위치 | `createStructured()`에 출력 검사 훅을 넣는다. 위반이면 throw해서 **기존 재시도 경로**를 탄다 | 생성 경로가 이 함수 하나로 모여 있다(기사 분석·리포트). 프롬프트 문구 추가는 이미 있는 규칙을 모델이 어긴 것이라 효과가 없다 |
| 검사 범위 | 파싱된 객체의 **모든 문자열 값**을 재귀로 본다 | 필드를 나열하면 새 필드가 생길 때 빠진다. keywords, topKeywords, title도 공개 텍스트다 |
| 오염 판정 | 한글·라틴·숫자·그리스 문자·기호는 정상. 그 밖의 문자(가나, 아랍, 칸나다, 키릴 등)는 바로 오염. 한자 덩어리는 ①입력 원문(기사 제목·설명, 리포트는 입력 기사 제목)에 있거나 ②「한글(漢字)」처럼 괄호 안에 단독으로 있거나 ③인용부호 안에 있거나 ④신문 약어(美·中·韓·日·北 등)일 때만 정상 | 과거 데이터에 정상 병기와 오염이 섞여 있다. 규칙은 R1 라벨로 보정하고, 라벨된 오염은 100% 잡고 라벨된 정상은 0건 걸리는 것을 통과 기준으로 둔다 |
| 끝까지 오염일 때 | 기사는 그 기사를 버린다(Stage 3 실패로 셈, 50% 임계 그대로). 리포트는 **작업 실패**(Workers 실패로 표시) | 「판정 실패를 메우지 않는다」 원칙. 글자만 지우면 「주의深이」 → 「주의이」처럼 문장이 깨진 채 공개된다. 3번 연속 오염 확률은 관측 빈도(리포트 1/12) 기준 사실상 0 |
| 10/12 리포트 | **다시 만들지 않고 깨진 토큰만 지운다** | 오염이 문장 끝에 붙은 토큰이라 지우면 원문이 그대로 복원된다. 재생성은 공개된 리포트 전체를 바꾸고 유료 호출과 판정을 다시 돈다. 앞 대화에서 「다시 만들겠다」고 했던 것을 이렇게 바꾼다 |
| 지난 데이터(P3) | R1 라벨에서 「오염」만 문장 단위로 손으로 고친 치환표를 만든다. 백업 후 적용 | 재분석은 기사 내용 전체를 바꾼다. 치환은 무엇을 바꿨는지 표로 남는다 |
| P5 고치는 방식 | 업서트 20개 트랜잭션 → `createMany({ skipDuplicates: true })` 한 번 | 지금 `update: {}`라 의미가 같다(있으면 건너뜀). 문장 하나라 트랜잭션 시간 한도가 없어지고, 반환 count가 정확한 신규 수가 된다 |

| **V1 크리틱** | Hermes `delegate_task`, 태스크마다 새 자식 | 같음 | 판정 파일 `docs/text-quality-fix/reviews/<ID>.md` 만 | PASS/FAIL, 고칠 것 목록(`path:line` + 재현), 같은 종류 결함 탐색 결과 |

규칙
- 저장소에 쓰는 것은 한 번에 W1 하나다. R1, R2, A1은 읽기 위주라 W1과 겹치지 않는 경로만 쓰고 병렬로 돈다.
- 자식의 「완료」는 자기 보고다. 다음 단계 전에 내가 같은 명령을 다시 돌리고 숫자를 직접 본다.
- 운영 DB 쓰기, OpenAI·Jev 실호출, 배포는 자식에게 주지 않는다. 검증 안 된 결과가 바로 공개 페이지에 나가기 때문이다.
- 자식이 운영 DB를 읽어야 하면(R1) 읽기 전용 쿼리 스크립트를 내가 미리 돌려 결과 파일을 넘긴다. 자식에게 `DATABASE_URL`을 주지 않는다.
- 하달 직전과 직후에 `git status --porcelain`을 찍어, 허용 경로 밖 변경이 있으면 그 산출물은 버리고 다시 하달한다.
