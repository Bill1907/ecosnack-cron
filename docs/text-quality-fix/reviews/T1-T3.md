## 3. 권고 (결함 아님)

1. **Script=Common 에 든 일본어 기호가 단독으로 나오면 새어 나간다.** 복사본이 아니라 import 로 실험한 결과는 다음과 같다.
   - 통과(미검출): `ー`(U+30FC) `・` `〆` `〜` `「」『』` `。` `、` `〃` `　`(U+3000) `ｰ` `ﾞ` `゛゜`, **`�`(U+FFFD, 깨진 토큰)**, ZWSP(U+200B). 예: `"매출이 늘었ー다"` → `[]`, `"올랐어요。그러나"` → `[]`, `"수익률이 �� 올랐어요"` → `[]`.
   - 검출: 가나와 붙으면 한 덩어리로 잡힌다(`"데이터ーです"` → `です`). `々` 는 Script=Han 이라 원문에 없으면 잡힌다(`"人々이"` → `人々`).
   - 운영 코퍼스(`spans.jsonl` 852개)에서 `。` 는 2건 있었고 둘 다 가나 옆이었다. 단독 사례는 0건이다. 다만 코퍼스 추출 정규식(`\P{L}` 제외)이 `。` `、` `�` 같은 비문자는 처음부터 보지 않았다. 그래서 「0건」은 측정된 값이 아니다. `\u3000-\u303F\u30FB\u30FC\uFF61-\uFF9F\uFFFD` 정도를 OK 집합에서 빼는 것을 권한다. 단, 「」는 한국 기사에도 쓰이므로 그 전에 H2 로 오탐을 확인한다.
2. **허용 목록에서 `美` 를 빼도 T2·T3 테스트는 실패하지 않는다.** 실패는 T1 테스트 3개뿐이다(아래 표). 「美 는 통과, 企業/電子 는 재시도」 테스트는 1회차 응답에 두 글자가 같이 있어서, 美 가 오염으로 판정돼도 호출 수(2회)가 같다. 「美 는 통과」 쪽을 확인하려면 美 만 있는 응답이 재시도 없이 1회로 끝나는지 따로 단언해야 한다.
3. **W1 보고서의 T3 설명이 코드와 다르다.** `reports/W1.md:115` 와 :149 는 source 가 「상위 30개 기사의 title + description」이라고 적었다. 실제 코드(`daily-report.ts:221`)는 `formattedArticles`(요약·핵심 포인트·영향·키워드 포함)와 제목·설명을 합친 것이다. 보고서 :149 의 「과거 오염이 리포트를 3회 실패시킬 수 있다」는 우려는 현재 코드에서는 반대로 「과거 오염이 통과한다」가 된다. 기록을 맞춰 두기를 권한다.
4. **리포트 source = 모델 입력 전체 설계는 수용 가능하다고 본다.** T2 배포 뒤 새 기사 분석문에 남는 한자는 그 기사 원문에 있거나, 한글 바로 뒤 괄호 병기이거나, 신문 약어뿐이다. 그래서 리포트로 옮겨지는 한자도 같은 범위로 묶인다. source 를 제목·설명만으로 좁히면 정상 병기(`多産多死`)를 옮긴 리포트가 3회 실패한다(테스트 `daily-report-script-guard.test.ts:178` 가 이 경우다). 위험은 T2 이전에 저장된 오염 행(라벨 47건)이 입력으로 들어가는 경우 하나뿐이다. **T6 치환을 적용하기 전에는 과거 날짜 리포트 백필(`--from/--to`)을 돌리지 않는다**는 순서 조건만 운영 절차에 적어 두면 충분하다.
5. **재시도와 타임아웃(기존 동작).** `withTimeout(withRetry(...))` 는 바깥 타임아웃이 나도 안쪽 재시도를 중단하지 않는다. 이 동작은 이번 변경 전부터 있었다. 오염 재시도가 늘면 기사 170초, 리포트 420초 뒤에도 유료 호출이 백그라운드에서 이어질 수 있다. H4 에서 `언어 오염 감지` 와 `타임아웃` 로그를 함께 본다.
6. `\d+\s*자\s*(이상|이내|…)` 는 원문 예외가 생겨도, 모델이 스스로 쓴 정상 문장(「비밀번호는 12자 이상」 류의 설명)에는 여전히 걸린다. 고칠 것 1을 반영한 뒤 H2 기사 prompt-leak 건수로 다시 판단한다.

## 4. 코드 검토 결과 (문제 없음 확인)

- **기존 재시도 경로**: validate 는 `finish_reason=length`·빈 응답 검사(:68)와 `schema.parse`(:74) **뒤**에서만 불린다. 그래서 잘림 재시도, Zod 실패 재시도, 400 비재시도(`isNonRetryableHttpError` 는 `status` 숫자만 본다. 「언어 오염」 Error 에는 status 가 없으므로 재시도 대상이다), 타임아웃 래핑은 그대로다. 테스트 「validate 가 없으면 이전과 같다」「비재시도 HTTP 오류(400)는 … 한 번만」과 기존 `judges.test.ts` 의 finish_reason=length 재시도, `with-timeout.test.ts` 가 모두 통과한다.
- **다른 createStructured 호출부**: `article-scoring.ts:88` 은 `{index, score}` 숫자, `evidence-validator.ts:51` 은 `verdict` enum 이다. 둘 다 validate 를 넘기지 않고, 공개 텍스트를 만들지 않는다. 영향 없음, 누락 없음.
- **성능** (`findForeignScript`, bun): 정상 3만 자 0.5ms, 가나 3만 자 0.1ms, 한자 1.5만+한글 1.5만 0.4ms. 최악 조건으로 한자/한글을 번갈아 놓은 3만 자(덩어리 1.5만 개)에 source 9만 자를 주면 66.9ms. `findForeignScriptDeep` 로 150자 문자열 200개, source 9만 자는 0.7ms. 정규식이 역추적으로 폭주하지 않는다(덩어리 정규식은 문자 클래스 반복이라 선형이다).
